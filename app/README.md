# Quest Cast — приложение и Android-клиент

Оболочка над движком `..\quest3-cast\quest3-cast.ps1`: окно на ПК с кнопками и
клиент на шлеме, который управляет кастом по локальной сети.

- `QuestCast\` — WPF-приложение (`QuestCast.exe`), 1020×700, тёмная тема.
- `QuestCastClient\` — Android-клиент (Java, без зависимостей), ставится на Quest 3.
- `QuestCast.cmd` — запуск приложения с нужными переменными окружения.
- `allow-firewall.cmd` — разовое правило брандмауэра на порт 47801 (нужны права администратора).
- `state\` — рабочие файлы движка (`runtime.json`, `cast.log`, `stats.json`, pid-файлы).

## Запуск

```
QuestCast.cmd
```

`QuestCast.cmd` выставляет `QUEST3CAST_STATE=<папка>\state` и `TMP/TEMP=<папка>\tmp`, потому что
GUI, запущенный из ограниченного контекста, не всегда имеет право писать в `%LOCALAPPDATA%`.
Приложение само поднимает диспетчер каста, если он ещё не запущен, и дальше держит его живым.

Приложение можно запускать и напрямую (`QuestCast\bin\Release\net10.0-windows\QuestCast.exe`) —
тогда состояние уйдёт в `%LOCALAPPDATA%\quest3-cast`, как у чисто консольного варианта.

## Кнопки

| Кнопка | Что делает |
|---|---|
| СТАРТ / СТОП | поднимает и гасит конвейер (scrcpy → mpv, линза и наклон применяются) |
| ПЕРЕЗАПУСК | стоп + старт, нужен после смены глаза, микрофона и линзы |
| МИКРОФОН ВКЛ / ВЫКЛЮЧИТЬ МИК | микрофон **по умолчанию выключен**; включение идёт через `--audio-source=mic` |
| ЛИНЗА ВКЛ / ЛИНЗА ВЫКЛ | коррекция дисторсии линзы (GPU-шейдер mpv) |
| КАЛИБРОВКА | замер наклона горизонта: 6 секунд записи, шлем не двигать; заодно ставит базу авто-горизонта |
| ОТКРЫТЬ ПОРТ | разовое правило брандмауэра для входящих подключений на порт управления |
| АВТО-ГОРИЗОНТ | держать горизонт по крену шлема из IMU-клиента (см. ниже) |
| ЗНАК КРЕНА | переворачивает направление подстройки, если горизонт уезжает не в ту сторону |
| ГЕЙН − / ГЕЙН + | сколько градусов картинки даёт градус крена (шаг 0.05); лечит остаточный крен |
| − 0.5° / + 0.5° | ручная юстировка наклона по контрольной линии |
| Левый / Правый / Оба | какой глаз показывать: кроп половины панели |

Индикатор `МИКРОФОН` в шапке показывает фактическое состояние записи звука (из `runtime.json`),
а не то, что записано в конфиге: уже запущенный конвейер держит своё значение до перезапуска.

## Авто-горизонт по гироскопу

Завал картинки — это сумма двух вещей: постоянный наклон самой панели внутри корпуса и крен шлема
в мире в момент съёмки. Первое меряет `КАЛИБРОВКА` (по картинке), второе умеет IMU шлема, поэтому
дальше горизонт держится сам.

**Что читает клиент.** У обычного 2D-приложения в шлеме нет ни одного стандартного датчика Android:
`getSensorList(TYPE_ACCELEROMETER)`, `TYPE_GYROSCOPE`, `TYPE_ROTATION_VECTOR` возвращают `null`
(позу отдаёт только OpenXR/VrApi). Зато виден вендорный сенсор `oculus.sensor.hmd_imu.2`
(тип 65537, имя — служебный JSON калибровки): 16 значений на событие, ~800 Гц, а в `values[1..3]`
лежит вектор гравитации в м/с². Отсюда крен считается как `atan2(x, -y)` — поворот вокруг оси
взгляда, — и тангаж `atan2(z, hypot(x, y))`. В `logcat` это видно как `QCTILT ev n=800 g=9.81`.

**Что летит по сети.** Клиент отправляет `{"type":"tilt","roll":-1.1,"pitch":4.5}` до 10 раз в
секунду в тот же сокет, что и команды. Сырой отсчёт шума даёт ±0.3°, поэтому клиент сначала
сглаживает крен (фильтр с постоянной ~60 мс по каждому отсчёту IMU) и только потом отдаёт его в
сеть: без этого картинка дёргалась на каждом повороте головы.

**Как это доезжает до картинки.** Движок держит `state/tilt.json` и генерирует `state/lens-live.glsl`:

```
deg = TiltBaseDeg + TiltSign * TiltGain * (roll - TiltBaseRoll)
```

`TiltGain` — не единица. Градус крена головы не даёт градуса поворота картинки: панель композитится
на изогнутой поверхности, коррекция линзы не является точной обратной функцией предыскажения, а оси
IMU не совпадают с осями панели. Всё вместе ведёт себя как неизвестный коэффициент передачи — именно
он и виден как «крен остался после поворота головы». Пока горизонт уезжает — жмите `ГЕЙН −`/`ГЕЙН +`,
пока картинка не начнёт точно повторять наклон головы (шаг 0.05, диапазон 0.4…1.8).

Pump видит новый `tilt.json`, генерирует шейдер и меняет его в уже работающем mpv по IPC
(`--input-ipc-server=\\.\pipe\quest3cast-ipc`, команды `change-list glsl-shaders clr ""` и
`append <файл>`). Перезапуска нет: кадр не дёргается, звук и связь не рвутся.

**Подбор гейна по цифрам.** Пока авто-горизонт включён, движок пишет `state/tiltlog.csv`
(`iso,imu_roll,tilt_deg`). Прогнать журнал через скрипт и получить готовое число:

```
python fit_tilt_gain.py                 :: возьмёт state\tiltlog.csv сам
python fit_tilt_gain.py путь.csv --current 1.0
```

Скрипт строит прямую по записанным точкам и печатает наклон (сколько градусов картинки на градус
крена), смещение и разброс. Разброс больше 1.5° означает, что виноват не гейн, а сглаживание или
сеть; меньше 0.5° — можно брать рекомендованный гейн и забыть про подстройку.

**Порядок работы.** Надеть шлем, смотреть ровно, нажать `АВТО-ГОРИЗОНТ`, затем `КАЛИБРОВКА` — она
замеряет наклон по картинке и одновременно запоминает текущий крен IMU как ноль. После этого крен
головы компенсируется автоматически. Если горизонт поехал не в ту сторону — `ЗНАК КРЕНА`.

Ограничения: гравитация даёт только крен и тангаж (рыскание — нет), у панели остаётся постоянный
наклон, который компенсируется базой, а точность ±1–2° — как у оптической калибровки. Пока шлем
лежит на столе, креномер измеряет крен стола, а не вашей головы.

**Почему нет автоматической подстройки по картинке.** Она написана (`TrimOnceAsync`, измерение кадра
через `level.py`) и выключена по умолчанию (`TrimEnabled`). Проверка на синтетических сетках с
известным поворотом показала, что оценщик ошибается на ±2–4° на малых углах и уводится чёрными
клиньями, которые срез повёрнутого кадра оставляет по краям: замкнутый контур по такому измерению
не убирает остаток, а вносит шум. Пока честнее подбирать гейн руками и по журналу.

## Сеть и протокол

Сервер слушает `0.0.0.0:47801` (порт меняется в `%APPDATA%\QuestCast\settings.json`).
Соединение — обычный TCP, сообщения — по одному JSON в строке.

```
← {"type":"hello","need":"token","app":"QuestCast","proto":1}
→ {"type":"auth","token":"<YOUR-TOKEN>"}
← {"type":"auth","ok":true}
→ {"type":"cmd","cmd":"start"}            // start | stop | restart
→ {"type":"cmd","cmd":"eye","value":"left"}   // left | right | both
→ {"type":"cmd","cmd":"mic","value":true}
→ {"type":"cmd","cmd":"lens","value":true}
→ {"type":"cmd","cmd":"calibrate"}
→ {"type":"cmd","cmd":"autolevel","value":true}    // авто-горизонт вкл/выкл
→ {"type":"cmd","cmd":"tiltsign","value":true}     // перевернуть знак крена
→ {"type":"cmd","cmd":"gain","value":1.15}         // сколько градусов картинки на градус крена
→ {"type":"cmd","cmd":"trim"}                      // разовый оптический замер (эксперимент)
→ {"type":"tilt","roll":-1.1,"pitch":4.5}         // клиент шлёт до 10 раз в секунду
→ {"type":"cmd","cmd":"state"}
← {"type":"ack","cmd":"start","ok":true,"message":"started ..."}
← {"type":"state","state":{"running":true,"fps":60,"mic":false,...}}   // каждую секунду
```

Токен генерируется один раз и лежит в настройках; он нужен любому клиенту.

### Брандмауэр

Windows не пускает входящие подключения к приложению, пока нет правила, а правило требует прав
администратора. Один раз нажмите **ОТКРЫТЬ ПОРТ** и подтвердите UAC — либо вручную:

```
allow-firewall.cmd
```

Без правила клиент на шлеме получит таймаут (ICMP тоже закрыт, поэтому `ping` с шлема не показатель).

### Обходной путь без администратора

```
adb -s <IP_шлема>:5555 reverse tcp:47801 tcp:47801
```

и в клиенте указать адрес `127.0.0.1`. Туннель живёт, пока подключён adb; после перезагрузки шлема
его надо поднять заново.

## Android-клиент

Экран: строка подключения (адрес, порт, токен), крупные кнопки СТАРТ / СТОП / МИК / ЛИНЗА,
выбор глаза, КАЛИБРОВКА, строка состояния и журнал на 8 строк. Настройки запоминаются в
`SharedPreferences` (`questcast`), при следующем запуске клиент подключается сам.

Сборка (SDK и JDK уже стоят на машине):

```
set ANDROID_HOME=C:\Android\Sdk
set JAVA_HOME=C:\Program Files\Microsoft\jdk-21.0.12.8-hotspot
cd QuestCastClient
%USERPROFILE%\.gradle\wrapper\dists\gradle-8.7-bin\<hash>\gradle-8.7\bin\gradle.bat assembleDebug
```

`--offline` не проходит: `aapt2` не лежит в кэше Gradle. Ставить без сети не получится.

```
adb -s <IP_шлема>:5555 install -r app\build\outputs\apk\debug\app-debug.apk
adb -s <IP_шлема>:5555 shell am start -n local.questcast.client/.MainActivity
```

Если нужно засеять настройки без ручного ввода:

```
adb shell am force-stop local.questcast.client
adb shell "run-as local.questcast.client sh -c 'cat /data/local/tmp/qc-prefs.xml > /data/data/local.questcast.client/shared_prefs/questcast.xml'"
```

Файл должен быть ровно в том виде, в каком его пишет Android: `port` — это `<int>`, а не `<string>`;
строка в этом поле раньше роняла клиент `ClassCastException` при старте.

## Грабли, на которые уже наступили

- `Start-Process -ArgumentList` склеивает аргументы без кавычек: строка с пробелом внутри
  (`--term-status-msg=STAT fps=...`) превращается в два аргумента.
- Ссылка на `Process.GetProcessById` для завершившегося pid бросает исключение — обработчик
  `FirstChanceException`, который писал лог, уходил в рекурсию и валил приложение
  переполнением стека.
- `WrapPanel` внутри `StackPanel` не переносит: он меряется бесконечной шириной, поэтому кнопки
  уезжали за правый край. Раскладка кнопок сделана сеткой.
- Без манифеста с `dpiAware`/`permonitorv2` окно на 125% растягивается битмапом и текст мылится.
- `Get-Content -Raw | Set-Content -Encoding UTF8` в PowerShell 5.1 портит кириллицу: XAML после
  такой правки пришлось восстанавливать перекодировкой и возвращать BOM.
- Датчики шлема отдают события только когда панель не спит: после `prox_close` поток идёт
  800 Гц, а на уснувшей панели `onSensorChanged` замолкает совсем.
- Android запрещает писать в сокет из главного потока (`NetworkOnMainThreadException`), а
  коллбэки сенсора приходят именно туда. Отдельно: поток `io` занят блокирующим чтением сокета,
  поэтому отправку крена пришлось вынести в собственный executor `tx` — задачи в `io` просто
  ждали в очереди и никогда не выполнялись.
- `%APPDATA%\QuestCast\settings.json` может остаться старым и недоступным на запись; настройки
  тогда уходят в `state\settings.json`, и читать надо сначала его, иначе авто-горизонт молча
  выключается при каждом старте.
