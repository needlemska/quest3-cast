# quest3-cast — картинка Quest 3 на ПК через ADB

Каст шлема без сервисов Meta: `scrcpy` снимает панель глаза по Wi-Fi ADB,
`mpv` показывает её в полный экран — уже с исправленной линзой и выправленным
горизонтом, декодируя видео на GPU (`d3d11va`) и кривя кадр вершинным шейдером.

Что нужно на ПК, кроме `scrcpy` и `adb`:

```powershell
winget install shinchiro.mpv          # плеер с GPU-декодом и glsl-шейдерами
winget install Gyan.FFmpeg            # только как запасной путь (ffplay)
```

## Файлы

| файл | что это |
|---|---|
| `quest3-cast.ps1` | сам сервис (демон + пульт: start/stop/status/install/shortcut) |
| `quest3-cast.cmd` | обёртка для запуска двойным щелчком |
| `quest3-pump.ps1` | конвейер: `scrcpy --record=\\.\pipe\quest3cast` → `mpv -` (или `ffplay -i pipe:0`) |
| `lens-template.glsl` | шейдер линзы и наклона; из него на каждом старте собирается `lens.glsl` |
| `quest3-overlay.ps1` | HUD в углу: fps, битрейт, cpu, ram, gpu, ping |
| `level.py` | оценка наклона горизонта по кадру (гистограмма направлений градиента) |
| `test-stability.ps1` | инъекция отказов: убить scrcpy/ffplay/HUD, дёрнуть adb — и замерить восстановление |
| `soak.ps1` | суточный/часовой сэмплер: fps, RSS по процессам, число перезапусков в CSV |
| `config.json` | настройки (`config.example.json` — шаблон, копируется в `config.json`) |

Состояние и логи: `%LOCALAPPDATA%\quest3-cast\` — `daemon.pid`, `scrcpy.pid`,
`overlay.pid`, `stats.json`, `cast.log`, `scrcpy.err.log`.

## Команды

```powershell
.\quest3-cast.cmd start      # поднять каст
.\quest3-cast.cmd stop       # погасить (и отпустить экран шлема)
.\quest3-cast.cmd status     # состояние
.\quest3-cast.cmd install    # автозапуск при входе в Windows
.\quest3-cast.cmd uninstall  # снять автозапуск и удалить ярлык с рабочего стола
.\quest3-cast.cmd shortcut   # ярлык "Quest 3 Cast" на рабочем столе
.\quest3-cast.cmd calibrate  # измерить наклон горизонта и записать его в rotateDeg
.\quest3-cast.cmd calibrate -Deg -3.5   # задать наклон вручную, без замера
```

Ярлык на рабочем столе и автозапуск вызывают `-Action start`, повторный вызов
безопасен: если демон уже работает, второй не поднимается.

## config.json

| ключ | смысл |
|---|---|
| `ip`, `port` | адрес шлема (Wi-Fi ADB, по умолчанию `:5555`) |
| `eye` | `left` / `right` / `both` — какое поле панели брать |
| `maxSize`, `fps`, `mbps` | размер длинной стороны, частота, битрейт |
| `angle` | поворот на стороне шлема: `0/90/180/270` — самый дешёвый |
| `rotateDeg` | наклон кадра в градусах; ставится командой `calibrate`, `0` — как снято |
| `lens` | `true` — исправлять линзу (mpv-шейдер или ffplay); `false` — сырое окно scrcpy |
| `lensK1`, `lensK2` | коэффициенты линзы; по умолчанию `-0.4` / `0` |
| `player` | `mpv` (GPU-декод + GPU-шейдер) или `ffplay` (всё на CPU, запасной путь) |
| `fullscreen` | `true` — плеер в полный экран |
| `audio` | `none` (по умолчанию, микрофон выключен) / `mic`; `output` на шлеме не работает (см. ограничения) |
| `audioBitrate` | кбит/с |
| `alwaysOnTop`, `windowX`, `windowY` | окно поверх, позиция |
| `overlay`, `overlayCorner`, `overlayOpacity` | HUD поверх картинки: `true/false`, угол `br/bl/tr/tl`, прозрачность `0.62` |
| `keepAwake` | не давать панели засыпать (`prox_close`) |
| `autoRestart`, `retrySeconds` | перезапуск конвейера и период переподключения |
| `maxUptimeHours` | `0` — не перезапускать никогда; `N` — перезапустить конвейер после N часов (лечит дрейф и утечки в долгом сеансе) |

Линза: `k1 < 0` — разгибает картинку (pincushion), `k1 > 0` — загибает.
Для Quest 3 около `-0.4`; сильнее — шире кадр, но заметнее мыло по краям.

## Наклон горизонта

Кадр панели почти всегда завален, и складывается он из двух вещей: физический
наклон самой панели в корпусе (кант линз, у Quest 3 — несколько градусов,
для шлема это константа) и наклон шлема относительно мира в момент съёмки.
На ПК видно сумму, поэтому `rotateDeg` — это не «правильный угол устройства»,
а «угол, при котором линза стоит ровно там, где вы смотрите».

```powershell
.\quest3-cast.cmd calibrate            # замер и запись в config.json
.\quest3-cast.cmd calibrate -Deg 3.5   # если рука/вкус точнее замера
```

Что делает `calibrate`:

1. пишет 6 с сырого кадра глаза (`scrcpy --record`, без линзы и без `rotateDeg`,
   поэтому повторный замер не накапливает поправку);
2. `ffmpeg` отдаёт кадры серым, `level.py` строит гистограмму направлений
   градиента по сильным границам (стены, монитор, панель дока) и берёт моду,
   сложенную по модулю 90°;
3. в `rotateDeg` уходит **противоположный** знак, сервис перезапускается.

Точность: ±1–2°, повторные замеры в одном положении дают разброс около градуса.
Ограничения метода: на однотонной стене без прямых линий замер бессмысленен
(`confidence` в выводе низкий), а вертикальный наклон (pitch) и поворот вокруг
оси взгляда (yaw) он не трогает — это другое искажение.

Порядок важен: сначала линза (`lensK1`), потом наклон — `rotateDeg` крутит уже
исправленный кадр. При смене положения шлема замер надо повторить: цифра
описывает положение, а не устройство.

## GPU-путь: mpv, d3d11va и шейдер

`ffplay` умеет только CPU-фильтры: `lenscorrection` — полнокадровый ресемпл
на всех ядрах, поэтому честный 1440p60 стоил ~2,4 ядра и ронял кадры. `mpv`
берёт декод на GPU AMD (`--hwdec=d3d11va`), а линзу и наклон считает фрагментным
шейдером `lens-template.glsl` — цена падает до **0,17 ядра** (замер на Ryzen AI
Z2 Extreme, 1440p60):

| путь | декод | линза | CPU |
|---|---|---|---|
| `ffplay -vf lenscorrection` | CPU | CPU-ресемпл | ~2,4 ядра |
| `mpv --hwdec=d3d11va --glsl-shaders` | GPU | GPU-шейдер | ~0,17 ядра |

Шейдер повторяет математику ffmpeg: радиус нормируется так, что в углу кадра
`r = 1`, поэтому `lensK1`/`lensK2` значат то же самое в обоих путях, и можно
переключать `player` без пересчёта коэффициентов. Кадр за пределами исходника
заливается чёрным — отсюда чёрные углы при сильном наклоне.

Мпв-специфика, на которой легко обжечься:

- `--profile=low-latency` **нельзя**: с ним mpv перестаёт отдавать
  `estimated-vf-fps`, и HUD остаётся без fps. `--cache=no` и
  `--demuxer-readahead-secs=0.4` безопасны и дают ту же задержку.
- `--terminal=yes` обязателен: без него mpv молчит в перенаправленный stdout,
  и конвейер не видит ни строки статуса.
- статус печатается шаблоном без пробелов (`STAT_fps=${estimated-vf-fps}`),
  иначе аргумент разваливается на два.

## HUD в углу

`quest3-overlay.ps1` — отдельное процессовое окно: без рамки, `TopMost`,
полупрозрачное, стоит в правом нижнем углу и обновляется дважды в секунду.

```
fps 60    vid 7 Mb/s
cpu 1%    ram 136 MB
gpu 32%   ping 3 ms
1440p60/mic/mpv
```

- `fps`, `vid` — из `stats.json`, который пишет `quest3-pump.ps1`
  (mpv отдаёт свой `estimated-vf-fps`, ffplay — число декодированных кадров;
  в обоих случаях это то, что реально дошло до экрана, и байты через трубу).
- `cpu`, `ram` — сумма по `scrcpy.exe` + плееру (`mpv.exe` или `ffplay.exe`);
  считается по времени процесса и рабочему набору, а не по счётчикам
  производительности: на русской Windows английские пути `\Processor(_Total)\…`
  не находятся.
- `gpu` — категория `GPU Engine` (она локали независима), `ping` — TCP-коннект
  до `ip:port` шлема.
- Окно висит и при упавшем конвейере: когда `stats.json` пропадает, `fps/vid`
  показывают `--`, а демон перезапускает HUD, если тот умер.
- HUD — layered-окно, поэтому его **не видно на скриншотах экрана** (DWM
  компонует его мимо GDI): на живой картинке он есть, в `CopyFromScreen` — нет.

## Стабильность

Что сервис делает сам, без человека:

| механизм | что лечит |
|---|---|
| переподключение adb | зомби-транспорт, выпавший Wi-Fi, перезагрузка шлема |
| распознавание `unauthorized` | шлем забыл ключ этого ПК: сервис не молотит `adb connect`, а раз в 5 минут пишет подсказку — нужен тап в шлеме |
| backoff `3 → 6 → 12 → 24 → 30` с | конвейер, умирающий сразу после старта, не устраивает шторм перезапусков |
| сторожевой по кадрам | зависший плеер или забитая труба: `stats.json` не обновлялся 25 с либо `0 fps` 20 с → перезапуск конвейера |
| сторожевой по HUD | окно HUD убито → поднимается за ~2 с |
| мьютекс демона | второй `start` не создаёт второй scrcpy на той же трубе |
| `try/catch` на итерации | любое исключение в цикле логируется и не роняет супервизор |
| `maxUptimeHours` | долгий сеанс: плановый перезапуск конвейера (дрейф и утечки) |
| `runtime.json` | `status` показывает фактический режим, звук, число перезапусков и uptime |

Замеры 27.10.2026 (Wi-Fi ADB, `1440p60`):

| сценарий | результат |
|---|---|
| убили `scrcpy` | картинка вернулась за 7,0 с |
| убили плеер (`mpv`) | 7,4 с |
| убили HUD | 1,9 с |
| `adb disconnect` | ~15 с (два перезапуска конвейера с backoff) |
| подвесили плеер (`NtSuspendProcess`) | зависание поймано за 26,4 с, конвейер перезапущен сам |
| плановый recycle (`maxUptimeHours = 0.005`) | сработал через 19 с |
| 10-минутный прогон, 40 замеров | fps 59–61, перезапусков 0, RSS плеера 105–126 МБ без роста, `pump` 81–82 МБ, HUD 111–116 МБ, лог 21 КБ |

Цена в CPU (Ryzen AI Z2 Extreme, `1440p60`): на `ffplay` с `-vf lenscorrection`
это ≈ 2,4 ядра, причём разрешение почти не помогает (≈ 2,1 на `1080p60` —
платит сам фильтр); на `mpv --hwdec=d3d11va` + GPU-шейдер — **≈ 0,17 ядра**.
`scrcpy` в обоих случаях ≈ 0,1 ядра. Замер: сумма `TotalProcessorTime` по
`scrcpy` + плееру за 20 с живого каста.

## Пойманные баги

Проход по коду 27.10.2026 — что было сломано и как проверено.

| дефект | как проявлялся | лечение |
|---|---|---|
| зомби-транспорт adb | после перезагрузки шлема `adb connect` отвечает «already connected», сокет мёртв, демон ждёт вечно | перед `connect` теперь идёт `adb disconnect` |
| пустой `daemon.pid` | `status`/`stop` падали на `.Trim()` у `$null` | чтение pid только через `Read-PidFile` с `TryParse` |
| переиспользованный pid | в pid-файле чужой процесс: `start` врал «already running», `stop` убивал постороннего | pid подтверждается командной строкой (`-Daemon`) |
| потерянный pid-файл | `stop` говорил «not running», демон жив и поднимал каст заново | `Stop-OrphanDaemons` в ветке `stop` |
| опечатка в `config.json` | демон падал при старте без записи в лог, HUD уходил в бесконечный перезапуск | `Repair-Config`: enum/числа/диапазоны чинятся и логируются |
| культура чисел | `TryParse("0.62")` на русской Windows = провал, `lensK1` тихо откатывался к `-0.4` | разбор в `InvariantCulture` |
| двойной `start` | два демона и два scrcpy на одной трубе, одно окно чёрное | сессионный мьютекс `quest3cast-daemon` |
| HUD при `lens: false` | статистики нет → HUD сам закрывался через 45 с, демон его поднимал: цикл | `-MaxIdle 0` для сырого режима |
| недочитанный `stats.json` | HUD ловил половину JSON, цифры мигали в `--` | запись во временный файл + `Move-Item` |
| `prox_close` после `kill -Force` | панель шлема оставалась включённой навсегда (садка батареи) | `Release-Display` в `stop`, если pid-файл пережил демона |
| молчаливая смерть демона | `start` писал «failed to start», в логе пусто | фатальная ошибка пишется в `cast.log`, `start` показывает её |
| `--profile=low-latency` у mpv | fps в HUD навсегда `0`: профиль отключает `estimated-vf-fps` | профиль убран, задержку держат `--cache=no` и `--demuxer-readahead-secs=0.4` |
| mpv без `--terminal=yes` | в перенаправленный stdout не приходит ни строки статуса | флаг добавлен всегда |
| шаблон статуса с пробелом | `--term-status-msg=STAT fps=…` разваливался на два аргумента, mpv искал файл `fps=…` | шаблон без пробелов: `STAT_fps=${estimated-vf-fps}` |
| `"--title=Quest3-" + $cfg.eye` в массиве аргументов | молча превращалось в два элемента (`--title=Quest3-`, `left`), mpv получал лишний вход | строка интерполируется: `"--title=Quest3-$($cfg.eye)"` |
| `\bfps=` в регулярке конвейера | `STAT_fps=` не матчится: перед `f` стоит `_`, границы слова нет | граница убрана из шаблона поиска |

Осталось известным и не лечится дёшево:

- `Stop-Stragglers` бьёт по любому `scrcpy`/`ffplay`/`mpv` с `Quest3-` в заголовке —
  руками запущенное окно с таким именем тоже закроется;
- `options` в `status` печатает `audio` из конфига; фактический звук смотрите в
  строке `runtime`;
- при выходе из Windows без `stop` команда `prox_open` не уходит: экран шлема
  может остаться разбуженным до перезагрузки;
- `adb` авторизация живёт на стороне шлема: если он «забыл» ПК (бывает после
  перезагрузки, если при первом запросе не отметить «всегда разрешать»), каст не
  поднимется без тапа в шлеме — сервис честно пишет об этом в лог и `status`.

## Найденные ограничения

- **Звук приложений шлема не отдаётся.** `--audio-source=output` падает внутри
  `AudioDirectCapture.startRecording` (AudioPlaybackCapture на Quest 3 прикрыт),
  поэтому по умолчанию `audio: "mic"` — это микрофон шлема, то есть звук комнаты.
  Системный звук каста возможен только через кастинг Meta или Virtual Desktop.
- **Наклон — это положение шлема, а не константа.** Кант панели даёт постоянную
  добавку, но основную часть угла даёт то, как шлем лежит или сидит. `calibrate`
  замеряет сумму в текущем положении; сдвинули шлем — замер повторяется.
  Поворот кадра оставляет по краям чёрные клинья (кадр становится ромбом) —
  это нормальная цена за ровный горизонт.
- **Декод и линза: CPU или GPU.** `ffplay` (запасной путь) декодирует и правит
  линзу на CPU: ~2,4 ядра и 5–8 сброшенных кадров в секунду при 1440p60.
  Путь по умолчанию — `mpv` с `d3d11va` и GPU-шейдером: ~0,17 ядра. Если mpv
  не установлен, сервис сам тихо откатывается на `ffplay`; `status` и `runtime`
  показывают, какой плеер реально работает.
- **`adb tcpip 5555` не выживает перезагрузку шлема** — нужен разовый USB-сеанс.
- Режим разработчика включается в Meta Horizon; `screencap`, `screenrecord` и
  `scrcpy` без `--display-id=0` на Horizon OS ≥ 74 дают чёрный кадр.
